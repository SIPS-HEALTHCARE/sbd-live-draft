# 2026-09-08: Read versus Take per module for Foundations and Instruments (#1123, Shawn board 137)

Problem:        Every Foundations / Instruments module is always the full 3-gate test
                (10-question Knowledge and Simulation draws, 3 passes each, leader-
                confirmed Observation). Board 137 wants a module that can be assigned
                as reading only. Endoscopy has a related idea (a chapter with no bank is
                "reading only for now", `endoHasQuiz`) but that is a content property,
                and its reading-only chapters never complete.

Options:        1. Mode on the assignment row ('read' | 'take', default take), chosen by
                   the leader in the assign picker. Read mode hides the gates; the
                   staffer confirms reading and the module completes.
                2. Module property like endoscopy (a flag on the module constant /
                   curriculum_modules row). Every staffer gets the same treatment for
                   that module; no leader choice.
                3. Leader marks a read-mode module done, like Scripts. Completion is
                   then a leader click, not "completes on reading".

Choice + why:   Option 1, as the issue text reads (assign as read only or as take the
                test). Shawn's board wording was NOT confirmed in this session; if 137
                means a module property, option 2 is a small follow-up (a flag on
                curriculum_modules that the picker pre-selects). Storage: one `mode`
                column on both assignment tables, RLS untouched. Completion: staff cannot
                PATCH the assignment row (the UPDATE policy is leaders only), so the
                confirmation is written on the progress row's g1 (owner-writable) and
                `sbd_fi_progress_guard` pins g2/g3 to a not-applicable pass for a read
                assignment, the same way #720 pins g2 for en-%. `complete` then falls
                out of the unchanged three-gate rule. The guard also mirrors `complete`
                onto assignment.status, which the client already sends but RLS silently
                dropped for staff writers; every counter in the app reads that status.

Not done:       One mode per assign batch (pick modules, pick one mode); mixed batches
                take two rounds. Reports (fiModuleSummary) show a read-complete module
                as complete with 0/3 passes; no separate "read" wording in reports.
                Switching an existing assignment between modes is not offered.
                Endoscopy keeps its own content-driven reading-only label.

Blast radius:   migration 20260908150000 (+1 column x2, guard replaced), foundations.js
                (assignModule signature +1 optional arg, 5 view edits, 6 small helpers),
                instruments.js (mirror), auth-init.js (+mode on 2 hydration maps),
                index.html cache-busts. Endoscopy and Scripts assignments ride
                foundations_assignments and default to 'take' (undefined mode -> take).
                Deploy order: migration BEFORE frontend (the INSERT body now carries
                `mode`).
