1How endoscopy works on the platform

Assignment only, by name. A leader assigns each endoscopy module to a named person. There is no belt trigger, no facility-wide rollout, and it is not part of the new-hire onboarding bundle. Someone who is never assigned a module never sees it. This is true in the first release because assignment is the mechanism, not a feature added on top: it is the same leader-assignment machinery that already runs Foundations, Instruments, and Preceptor today. No new architecture.

This is also the clean version of the split you raised: belt continues to trigger the belt curriculum, and endoscopy becomes the first content that exists only on the leader-assigned side.

Once assigned, each module has the standard three gates — identical mechanics to Foundations:

GateWhat it isPass rule
1 · Knowledge10 questions drawn at random from the module's bank of 25Score 80%+, three passing attempts
2 · Simulation10 scenario questions drawn from the module's bank of 25Score 80%+, three passing attempts
3 · ObservationA leader confirms each checklist item in personUnlocks after Gates 1 and 2; every item confirmed

A module is complete when all three gates are passed. Because each attempt draws a fresh random ten from the bank, the three attempts are not the same test three times.

3What each module needs, and in what format

Four things per module. The reader document converts into the platform automatically if the format below is followed — it is the same format as the ten Foundations documents from 4 August, so it is the format Dr. Jake has already written in once.

A. Reader document — one Word (.docx) file per module

  • Filename: SIPS_Endoscopy_Module1_Fundamentals.docx and so on — the Module1, Module2 part matters.
  • Each numbered section starts with a Heading 1 styled paragraph numbered 1.1, 1.2, … Each Heading 1 becomes one readable section on screen.
  • Subheadings use Heading 2 and Heading 3 styles.
  • Bullet points as real Word lists, not typed dashes.
  • Tabular information as real multi-column Word tables — these render as tables on screen.
  • Callout boxes: a single-cell table whose text starts with one of three symbols, which sets the color and is then removed: ⚠ warning (red), 💡 tip / SBD standard (green), 📚 key point (blue).

B. Knowledge question bank — 25 multiple-choice questions per module

Four options each, correct answer marked. Twenty-five matches the Foundations standard; if time is short, fifteen by the 21st is workable and the remainder can follow after go-live.

C. Simulation bank — 25 scenario questions per module

A short workplace situation, four possible responses, the best response marked. Same fallback as B if time is short.

D. Observation checklist — 5 to 7 items per module

Each item one observable statement a leader can confirm by watching the person work, e.g. "Performs a leak test per the scope's IFU before manual cleaning." These become the Gate 3 items.

B, C, and D can sit at the end of each module's Word document or arrive as a separate document or spreadsheet — whatever is easiest to write, as long as each is clearly labeled with its module, questions are numbered, and the correct answer is marked.

If any module should carry video: send links or embed codes only — hosting stays on your side, as agreed previously. The embedding surface is a separate piece of work and is not required for the 28 August release.
